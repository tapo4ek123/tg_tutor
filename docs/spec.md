# Спецификация MVP SkillPilot

Пользователь самостоятельно изучает навык и нуждается в последовательности тем,
практике и обратной связи. Основной проверяемый сценарий — основы Go;
другие текстовые предметы принимаются, но требуют отдельного предметного Eval.

## Сценарий

1. `/skills`: список и переключение; `/newskill` добавляет независимый навык.
   `/start`: цель → опыт → бюджет времени → срок.
2. GPT-6 Luna составляет 2–4 диагностических вопроса.
3. После ответа формируется план из 3–6 этапов; последний — итоговая работа.
4. Пользователь принимает план и получает объяснение, пример и задание.
5. Ответ оценивается по неизменной рубрике задания. Балл рассчитывает код. Рубрика, эталон и отдельные оценки скрыты;
   ученик получает общий результат и обратную связь.
6. <80% → целевая дополнительная практика; ≥80% → следующий этап.
7. Итоговая работа засчитывается только без подсказок.
8. $3 в сутки на модель для всего приложения; резерв до вызова, учёт usage после.
   При исчерпании шаг сохраняется, кнопка проверяет лимит и продолжает. Сброс в 00:00 Москвы.
9. Расписание с часовым поясом хранится в БД, напоминания отправляет сервер.

## Навигация

Клавиатура Telegram открывает основные действия без знания команд.
«Скрыть меню» убирает её; `/menu`, `/start` или «Главное меню» показывают снова.
Обычные сообщения не раскрывают меню автоматически.
`/start` показывает короткое приветствие и текущий шаг; `/menu` — главное меню,
`/continue` восстанавливает вопросы, план или занятие. Настройка навыка имеет четыре
пронумерованных шага, варианты ответа и возврат к предыдущему вопросу.
В занятии показаны навык, номер этапа и кнопки следующего действия.
«Задать вопрос» сохраняет режим ввода внутри навыка: следующее обычное сообщение
идёт в ask, а не grade. Успешный ответ или отмена возвращает режим решения.
Режим сохраняется после рестарта и переключения. Старые учебные кнопки проверяют
revision; старые кнопки просмотра показывают актуальные данные.
Напоминания настраиваются готовыми кнопками либо прежней текстовой командой.

## Критерии приёмки

- Нажатия меню не становятся учебными ответами и не изменяют прогресс.
- «Продолжить» повторно показывает существующее задание без нового LLM-вызова.
- Ввод вопроса не создаёт попытку проверки; отмена не засчитывается как помощь.
- Каждый навык хранит собственные профиль, план, урок, подсказки и попытки.
- Состояние и финансовый журнал сохраняются после перезапуска.
- Миграция прежней цели сохраняет план и прогресс. Удаление затрагивает выбранный навык.
- Рубрика и баллы отдельных критериев отсутствуют в сообщениях ученику.
- Атомарные резервы не допускают параллельных запросов сверх остатка бюджета.
- Usage учитывается даже при ошибке формата ответа; неизвестный расход учитывается по резерву.
- Кнопка продолжения восстанавливает шаг после смены суток и перезапуска.
- Бюджет общий для этого приложения; расходы других приложений аккаунта не видны.
- Два пользователя не получают данные друг друга; бот работает только в личных чатах.
- Двойное нажатие не создаёт две попытки; запросы одного пользователя сериализуются.
- Некорректный ответ провайдера не переводит ученика на следующий этап.
- Неверное количество оценок или несовпадение критериев отклоняется.
- MCP — реальный stdio-процесс официального SDK; основные чтения и записи идут через него.
- Напоминания учитывают дни недели и IANA timezone, имеют retry и отключение.
- В репозитории нет токенов; есть Docker, lock-файл, тесты, Eval и презентация.

## Ограничения

Текстовые задания; несколько параллельных навыков, один выбран для текущего диалога; проверка кода без исполнения; нет голоса,
браузерного поиска и автоматической сертификации навыка. Прогресс — доля пройденных
этапов, а не объективный процент знания. LLM-оценка требует предметной верификации.
Один экземпляр бота и MCP на постоянном сервере, SQLite на persistent volume.

## SDD

Спецификация → архитектура → задачи → реализация → автоматическая проверка.
Изменения требований фиксируются здесь до изменения поведения.
